# Creating a new microservice

Follow these steps exactly, so all services look the same.
Back to the [README](../README.md) · Workflow rules: [CONTRIBUTING.md](../CONTRIBUTING.md)

> **How our Maven setup works:** the root `alert-hub/pom.xml` is both the **parent** and the **aggregator** of every service.
> It inherits from `spring-boot-starter-parent` 4.1.2, sets Java 25, provides the dependencies every service needs, and manages the versions of the rest.
> Every service inherits from `alert-hub`, **not** directly from `spring-boot-starter-parent`.
>
> ```text
> spring-boot-starter-parent (4.1.2)
>               |
>        alert-hub (root pom.xml)
>        Parent + Aggregator
>               |
>     ---------------------
>     |         |         |
>   loader   security    user   ...
> ```

---

## 1. Create a branch

Create a task in Notion first, then:

```bash
git checkout main
git pull
git checkout -b chore/AH-<id>-<name>-service-scaffold
```

Example: `chore/AH-7-security-service-scaffold`

---

## 2. Generate the project in IntelliJ

**File → New → Project → Spring Boot**, then fill in:

| Field | Value |
|---|---|
| Name | `<name>-service` (e.g. `security-service`) |
| Location | `.../alert-hub/services` |
| Create Git repository | ❌ **unticked** (alert-hub is already a Git repo) |
| Language | Java |
| Type | **Maven** |
| Group | `com.mst.alerthub` |
| Artifact | `<name>-service` |
| Package name | `com.mst.alerthub.<name>`, with **no dashes** (e.g. `com.mst.alerthub.emailsender`). IntelliJ fills this in wrong by default, so change it by hand |
| JDK | **Eclipse Temurin 25** |
| Java | **25** (not "25 Preview") |
| Packaging | Jar |
| Configuration | Properties |

Click **Next**, choose **Spring Boot 4.1.2**, and pick **only the dependencies for your kind of service**:

| Service | Dependencies to pick in IntelliJ |
|---|---|
| Every service | Nothing: these come from the root `pom.xml` automatically (see step 3) |
| + services with a database (loader, security, user, metric, action) | Spring Data JPA, PostgreSQL Driver |
| + logger | Spring Data MongoDB |
| + services that call others (processor, evaluation, user, action) | OpenFeign |

Click **Create**. If IntelliJ asks how to open it, choose **This Window**.

## 3. Switch the service to the Alert Hub parent

IntelliJ always generates the service with Spring Boot as its parent:

```xml
<!-- generated by IntelliJ: REMOVE this -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.2</version>
    <relativePath/> <!-- lookup parent from repository -->
</parent>
```

Open `services/<name>-service/pom.xml` and replace it with the Alert Hub parent:

```xml
<!-- use this instead -->
<parent>
    <groupId>com.mst.alerthub</groupId>
    <artifactId>alert-hub</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <relativePath>../../pom.xml</relativePath>
</parent>
```

**Why `../../pom.xml`:** the service lives in `alert-hub/services/<name>-service/`, so the root `pom.xml` is two folders up (`<name>-service` → `services` → `alert-hub`).
With the wrong path, Maven looks for `alert-hub` in the remote repository and the build fails.

Then clean up the rest of the generated `pom.xml`:

- **Keep** `<artifactId><name>-service</artifactId>`. Do not rename it.
- **Delete** `<java.version>25</java.version>` from `<properties>` (and the whole `<properties>` block if it's then empty). The root sets Java 25 for everyone.
- **Delete** any dependency that the root already provides (list below). Declaring it again creates duplicates.
- **Delete** generated Lombok build configuration (the Lombok `annotationProcessorPaths` in `maven-compiler-plugin`, and the Lombok `<exclude>` in `spring-boot-maven-plugin`) if the root `pom.xml` already has it.
- **Keep** the `spring-boot-maven-plugin` in `<build>`, without a `<version>`: the root manages plugin versions.

### Inherited automatically (do NOT add these to the service)

Every service gets these from the root `pom.xml`:

| Dependency | Notes |
|---|---|
| Spring Web | |
| Lombok | `optional`: compile time only, not packaged in the jar |
| Validation | |
| Spring Boot DevTools | `optional`: for local development only, not packaged in the jar |
| Spring Boot Actuator | |
| Spring for Apache Kafka | |

If you're unsure, open the root `pom.xml`: anything in its top-level `<dependencies>` section is inherited, so delete it from your service.

### Stays in the service `pom.xml`

Dependencies that only some services need stay in that service's `pom.xml`: JPA + PostgreSQL, MongoDB, OpenFeign, Swagger (step 4), and anything else specific to the service.
Never move them to the root `<dependencies>`, or every service would get them.

## 4. Add Swagger (not needed for logger)

In `services/<name>-service/pom.xml`, add this inside `<dependencies>`:

```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
</dependency>
```

**Don't write a `<version>`.** The root `pom.xml` manages the springdoc version in `<dependencyManagement>`, so all services use the same one. To upgrade Swagger, change it once in the root.

After the service runs, Swagger UI is at `http://localhost:<port>/swagger-ui.html`.

---

## 5. Register the service in the root `pom.xml`

In `alert-hub/pom.xml`, remove the comment around your service's line:

```xml
<!-- before -->
<!-- <module>services/security-service</module> -->

<!-- after -->
<module>services/security-service</module>
```

This lets IntelliJ load the service as a Maven module.
Only do this in the same PR that creates the folder: Maven fails if a listed folder doesn't exist.

---

## 6. Add the CI workflow

1. Copy `.github/workflows/loader-service.yml` to `.github/workflows/<name>-service.yml`
2. Replace **every** `loader` with your service name (name, `paths`, `working-directory`, `loader_db`)
3. If your service has **no database** (processor, evaluation, email-sender, sms-sender): delete the `services: postgres` block and the three `SPRING_DATASOURCE_…` lines

---

## 7. Set the basic configuration

In `services/<name>-service/src/main/resources/application.properties`:

```properties
spring.application.name=<name>-service
server.port=<port from the README ports table>
```

Services with a database also need the connection settings. Read the password from an environment variable, never write it in the file:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/<name>_db
spring.datasource.username=${DB_USER:postgres}
spring.datasource.password=${DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=update
```

---

## 8. Check, commit, open a pull request

- Delete the generated `HELP.md`
- In IntelliJ: **Maven** tool window → 🔄 **Reload All Maven Projects**; your service appears as a module **under `alert-hub`**
- From the `alert-hub` root, check that Maven accepts the new parent:

  ```bash
  ./mvnw validate          # macOS / Linux
  mvnw.cmd validate        # Windows
  ```

- Check that `git status` shows no `.idea/` or `target/` files

```bash
git add .
git commit -m "chore(<name>): scaffold <name>-service (AH-<id>)"
git push -u origin chore/AH-<id>-<name>-service-scaffold
```

On GitHub: **Compare & pull request** → title `chore(<name>): scaffold <name>-service (AH-<id>)` → a maintainer reviews and merges.
In Notion: set the task to *In Review* and paste the PR link.

> **Note:** for services with a database, `./mvnw verify` fails locally until PostgreSQL runs in Minikube, because the generated test connects to the database. The CI on GitHub provides its own temporary database, so the PR check still passes.

## Reviewer checklist

- [ ] `<parent>` is `com.mst.alerthub:alert-hub:1.0.0-SNAPSHOT` with `<relativePath>../../pom.xml</relativePath>`
- [ ] No `spring-boot-starter-parent` and no `<java.version>` in the service `pom.xml`
- [ ] `artifactId` is `<name>-service`
- [ ] Package is `com.mst.alerthub.<name>`
- [ ] No inherited dependencies repeated (Web, Lombok, Validation, DevTools, Actuator, Kafka)
- [ ] Only the service's own extra dependencies are declared (JPA + PostgreSQL / MongoDB / OpenFeign as the table says)
- [ ] springdoc dependency present **without a `<version>`** (except logger)
- [ ] Module line uncommented in the root `pom.xml`
- [ ] `./mvnw validate` passes from the root
- [ ] Workflow file added and all `loader` references replaced
- [ ] No `HELP.md`, `.idea/`, `target/` or passwords committed
